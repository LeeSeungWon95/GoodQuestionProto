# 굿퀘스천 — 프로젝트 개요 및 기능 요구사항

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | 굿퀘스천 (Good Question) |
| 한 줄 소개 | 아이들의 말하기 교육 공백을 채우는 **이야기 기반 AI 말하기·문해력 교육 웹 서비스** |
| 대상 사용자 | 초등학교 저학년 아이 (학습자) + 보호자 (계정 소유·결과 확인) |
| 핵심 가치 | 이야기 속 캐릭터와의 음성 대화를 통해 아이의 생각·이유·감정 표현을 이끌어내는 "좋은 질문" 경험 |
| 차별화 | 국내 초등 저학년 대상 '말하기 전용' 온라인 서비스는 거의 전무. 기존 디지털 교육(아이스크림 홈런, 밀크T 등)은 읽기·쓰기 중심 |
| 경쟁 제품 | 카티어스 카티(영유아 감정형 AI 대화), 모두의 한국어(종합 한국어 교육), 웅진 북스토리(AR 체험형 독서), 아이스크림 홈런 북카페(디지털 독서) |
| 플랫폼 | 웹 앱 — 확정. 지원 기기: 1순위 iPad·안드로이드 태블릿, 2순위 PC·노트북, 3순위 스마트폰 |
| MVP 콘텐츠 | 「방귀 뀌는 며느리」 1편 — 장면 9개(도입 1, 전개 4, 대화 4), 미션 2개, 예상 20분 |
| 핵심 학습 루프 | 이야기 선택 → 장면 진행(캐릭터 질문) → 아이 음성 답변(STT) → 발화 분석 → 추가 질문 or 다음 장면 → 말하기 후 활동(카드 배열 + 재구성 말하기) |

## 2. 기능 요구사항 표

우선순위: **필수** = MVP 구현 대상 / **추가** = 이번 단계에서는 설계만 반영, 구현은 후순위

| ID | 구분 | 요구사항명 | 주요 기능 | 상세 |
|---|---|---|---|---|
| FR-01 | 필수 | 회원가입 및 아이 등록 | 보호자 계정 생성·아이 프로필 관리 | 이메일 또는 소셜 로그인(카카오·구글·네이버 중 1개 이상). 보호자 계정 아래 여러 아이 프로필 등록(이름, 나이) |
| FR-02 | 필수 | 메인 화면 | 이어하기·추천 이야기 | 진행 중 이야기 + 이어하기 버튼. 추천 이야기 2~3개 표시(추천 로직은 미구현, UI 영역만 배치). 탭: 홈/이야기/단어장/마이페이지 |
| FR-03 | 필수 | 이야기 선택 | 이야기 목록·상세 안내 | 목록에 대표 이미지·제목·예상 시간·주요 주제 표시, 주제별 필터. 상세 화면에 도입·상황·아이 역할 표시 |
| FR-04 | 필수 | 이야기 장면 진행 | 장면·캐릭터 질문 | 화면 유형 3종: 도입(전체 화면 내레이션) / 전개(스토리, 좌측) / 대화(캐릭터, 우측). 전개 종료 후 대화 영역 활성화. 장면 이미지·캐릭터 표시, 상황 설명·캐릭터 대사 제공. 캐릭터 음성 자동 재생(TTS), 다시 듣기 제공. 장면별 고정 첫 대사·고정 마지막 대사 사용 |
| FR-05 | 필수 | 아이 음성 대화 | 음성 입력·텍스트 변환 | 캐릭터 발화 종료 후 효과음·화면 변화와 함께 마이크 자동 활성화. 음성을 텍스트로 변환(STT)해 표시. 보내기 버튼으로 발화 확정·제출. 아이/캐릭터 대화 내역 구분 표시. 발화 원문 세션 저장 |
| FR-06 | 필수 | 발화 분석 및 캐릭터 반응 | 발화 분석·추가 질문·장면 전환 | 발화에서 사고 요소 8종(DECISION·REASON·PERSPECTIVE·SOLUTION·RESULT·EMOTION·EMPATHY·REQUEST) 추출, 장면의 required_elements와 비교해 **여러 발화에 걸쳐 누적 확인**. LLM은 의도·핵심 뜻·요소·발화 유효성(VALID/SHORT/UNCLEAR/OFF_TOPIC/PLAYFUL)만 제안하고, 목표 충족·응답 모드(NORMAL/GUIDED/CLOSING)·종료 이유(GOAL_MET/MAX_TURNS)는 서버 규칙으로 판정. 미충족 시 캐릭터 성격 유지한 유도 질문(신규 요소 없음 2연속 또는 저정보 발화 2연속 시 유도). preferred_turns 이상 + 요소 충족 시 또는 max_turns 도달 시 고정 마지막 대사 재생 후 다음 장면. ※ 판정 규칙 상세: `06-dialogue-engine.md` |
| FR-11 | 필수 | 이야기 내 미션 | 대화 중 조건부 미션 노출 | 대화 시작과 동시에 노출하지 않고, 아이 발화 흐름 확인 후 해결 방법을 구체화해야 하는 시점에 노출(예: 해결 방향만 있고 방법이 불구체적, 2회 이상 대화에도 실행 방법 없음). 미션 결과는 정답 여부가 아닌 사고 요소 확인에 활용. MVP 콘텐츠 기준 대화3(방귀 활용 해결책 구성)·대화4(단점을 장점으로 바꾸기) 2개 |
| FR-07 | 필수 | 말하기 후 활동 | 이야기 재구성·생각 정리 | 주요 장면 카드 4~5개 무작위 제시 → 아이가 순서대로 배열 → 정답 시 핵심 단어 3~4개 제공 → 카드·단어를 참고해 전체 이야기를 음성으로 재구성 → 텍스트 전환·표시 → 발화 내용·완료 여부 저장 |
| FR-08 | 추가 | 보호자 리포트 | 활동 결과·발화 변화 | 화면 흐름도 기준 구성: 말하기 역량 분석(어휘·논리·표현), 대표 발화 확인, 가정 학습 가이드 |
| FR-09 | 추가 | 단어 저장 | 모르는 단어 저장·확인 | 대화 중 모르는 단어 질문 시 저장. 쉬운 뜻·이야기 속 예문·음성 듣기 제공. 좋아하는 단어 저장. 별도 단어장 화면은 후순위 |
| FR-10 | 추가 | 캐릭터 마음 변화 | 표정·태도 변화 | 아이 발화에 따라 캐릭터 표정·태도 변화 (몰입도 향상 목적) |
| FR-12 | 추가 | 설정 및 기타 | 부가 화면 | 설정, 공지사항, 고객센터, 이용 안내, 로그아웃 (화면 흐름도 기준 — 시연 필수 아님, 정적 화면으로 최소 구현 가능) |

FR-01 보충 (화면 흐름도 기준): 로그인 후 **아이 선택 화면**을 거쳐 홈으로 진입. 회원가입 경로는 보호자 계정 생성 → 아이 프로필 등록 → 아이 선택 → 홈. 아이 등록 시 **아동 개인정보 처리 동의**(child_consents) 기록 필요 — 동의 없거나 철회된 아이는 세션 시작 불가 (팀 DB안).

## 3. 비기능 요구사항 (파악 과정에서 도출)

| ID | 항목 | 내용 |
|---|---|---|
| NFR-01 | 보안 | HTTPS 필수 (마이크 권한이 secure context에서만 동작) |
| NFR-02 | 개인정보 | 아동 데이터(이름·나이·발화) 최소 수집. 오디오 원문 미저장, STT 텍스트만 저장 |
| NFR-03 | 응답성 | STT→분석→TTS 체인 지연 동안 아이가 이탈하지 않도록 로딩 연출(캐릭터 애니메이션 등) 제공 |
| NFR-04 | 사용성 | 저학년 아동 기준 UI: 큰 터치 영역, 텍스트 최소화, 음성 안내 중심 |
| NFR-05 | 호환성 | 1순위 기기(iPad Safari·안드로이드 태블릿 Chrome)에서 녹음·재생 동작 보장. iPad Safari는 MediaRecorder 포맷(audio/mp4)과 오디오 자동 재생 제한(사용자 제스처 필요) 대응 |
| NFR-06 | 화면 | 태블릿 가로 화면 기준 좌(전개)/우(대화) 분할 레이아웃 |
| NFR-07 | 상태 표시 | 아이 발화 중 / 음성 변환 중 / 캐릭터 응답 대기 등 현재 진행 상태를 분명하게 구분 표시. 아이가 말할 차례를 시각·청각으로 명확히 안내 (고객 인터뷰 근거) |
| NFR-08 | 정보 제시 | 긴 설명은 한 문장씩 단계 제시. 현재 단계에서 필요한 행동(버튼) 하나만 노출. 상세: `05-ux-guidelines.md` |
