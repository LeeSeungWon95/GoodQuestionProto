## 1. 시스템 구성 파악

시스템을 기간 업무(핵심)와 지원 업무로 구분한다.

| 구분 | 업무 영역 | 설명 |
|---|---|---|
| 기간 업무 | 학습 진행 | 이야기 선택 → 장면 진행 → 음성 대화 → 발화 분석 → 말하기 후 활동으로 이어지는 핵심 학습 루프 |
| 기간 업무 | 발화 분석 | 아이 발화에서 사고 요소를 추출하고 장면 목표와 비교, 캐릭터 반응·진행을 결정 |
| 기간 업무 | 콘텐츠 관리 | 이야기·장면·캐릭터 대사·목표 발화 조건 데이터 (MVP에서는 시드 데이터로 관리) |
| 지원 업무 | 회원/프로필 관리 | 보호자 계정 생성, 아이 프로필 등록·관리 |
| 지원 업무 | 리포트·단어장 | 보호자 리포트, 단어 저장 (추가 요건 — 설계만 반영) |

## 2. 시스템 기능 파악

주요 기능과 하위 기능의 계층 구조. (상세 요구사항 표는 `01-project-overview.md` 참조)

```
굿퀘스천
├─ 회원/프로필        ├─ 보호자 가입·로그인 (Supabase Auth — 이메일 또는 소셜 1개 이상)
│                     ├─ 아이 프로필 다중 등록 (이름, 출생연도) + 아동 개인정보 처리 동의 기록
│                     └─ 아이 선택 화면 (로그인 후 / 프로필 등록 후 → 홈 진입)
├─ 메인 화면          ├─ 이어하기 (진행 중 이야기)
│                     ├─ 추천 이야기 2~3개 (추천 로직 미구현, UI 영역만)
│                     └─ 탭: 홈 / 이야기 / 단어장 / 마이페이지
├─ 이야기 선택        ├─ 목록 (대표 이미지·제목·예상 시간·주제) + 주제별 필터
│                     └─ 상세 (도입, 상황, 아이 역할)
├─ 이야기 장면 진행   ├─ 화면 유형 3종: 도입(전체 화면) / 전개(스토리, 좌측) / 대화(캐릭터, 우측)
│                     ├─ 전개·대화는 한 화면에 배치하되 순차 진행 (전개 종료 → 대화 활성화)
│                     ├─ 장면 이미지·캐릭터·상황 설명·대사 표시
│                     ├─ 캐릭터 음성 자동 재생(TTS) + 다시 듣기
│                     └─ 이야기 내 미션: 대화 중 조건 충족 시 노출 (예: 해결 방법 구체화 필요 시)
├─ 아이 음성 대화     ├─ 캐릭터 발화 종료 → 효과음·화면 변화 → 마이크 자동 활성화
│                     ├─ 음성 → 텍스트 변환(STT) 후 화면 표시
│                     ├─ 보내기 버튼으로 발화 확정·제출
│                     └─ 대화 내역 구분 표시, 발화 원문 세션 저장
├─ 발화 분석·캐릭터 반응
│                     ├─ 사고 요소 추출 (생각·이유·감정·관점·판단·해결 방법)
│                     ├─ 장면의 목표 발화 조건과 비교
│                     ├─ 미충족 → 캐릭터 성격·입장 유지한 추가 질문 생성
│                     ├─ 충족 또는 최대 대화 횟수 도달 → 다음 장면 전환
│                     └─ 마지막 장면 완료 → 전체 대화·분석 저장 → 말하기 후 활동
└─ 말하기 후 활동     ├─ 장면 카드 4~5개 무작위 제시 → 순서 배열
                      ├─ 정답 시 핵심 단어 3~4개 제공
                      └─ 카드·단어 참고해 이야기 음성 재구성 → 텍스트 표시·저장

[추가 요건 — 설계만 반영]
├─ 보호자 리포트: 말하기 역량 분석(어휘·논리·표현) / 대표 발화 확인 / 가정 학습 가이드
├─ 단어 저장: 모르는 단어 저장, 쉬운 뜻·예문·음성 듣기, 좋아하는 단어 (단어장 화면 후순위)
├─ 캐릭터 마음 변화: 발화에 따른 표정·태도 변화 (몰입도 향상)
└─ 설정 및 기타: 설정 / 공지사항 / 고객센터 / 이용 안내 / 로그아웃 (화면 흐름도 기준)
```

## 3. 시스템 인터페이스 파악

| ID | 송신 → 수신 | 데이터 | 방식/포맷 | 주기 |
|---|---|---|---|---|
| IF-01 | 웹 클라이언트 → API 서버 | 인증, 프로필, 이야기 조회, 세션 진행 | HTTPS REST / JSON | 요청 시 |
| IF-02 | 웹 클라이언트 → API 서버 | 아이 발화 오디오 | HTTPS multipart (webm/mp3) | 발화 제출 시 |
| IF-03 | API 서버 → OpenAI STT | 오디오 → 텍스트 | HTTPS / OpenAI API (Whisper 계열) | 발화 제출 시 |
| IF-04 | API 서버 → OpenAI GPT | 발화 텍스트 + 장면 목표 → 분석 결과·추가 질문 | HTTPS / JSON (structured output) | 발화 제출 시 |
| IF-05 | API 서버 → OpenAI TTS | 캐릭터 대사 텍스트 → 음성 | HTTPS / audio | 장면 진입·질문 생성 시 |
| IF-06 | 웹 클라이언트 ↔ Supabase Auth | 가입·로그인·소셜 OAuth·JWT 발급 | Supabase SDK / OAuth 2.0 | 로그인 시 |
| IF-07 | API 서버 ↔ DB (Supabase PostgreSQL) | 전체 영속 데이터 | SQL / Supabase JWT 검증 | 상시 |

- 실시간 양방향(WebSocket)은 MVP에 불필요 — 대화가 턴 기반(제출 → 응답)이므로 요청-응답으로 충분.
- STT→분석→TTS 체인 지연 대응으로 응답 스트리밍(SSE)은 선택 사항으로 남긴다.

## 4. 시스템 아키텍처 파악

- **구조**: 3계층 (웹 SPA — API 서버 — DB) + Supabase(Auth/DB) + 외부 AI API
- **웹 서버(정적 호스팅)의 위치**: SPA도 최초 진입 시 `index.html`·JS 번들·CSS를 내려주는 웹 서버가 반드시 필요하다. 이 JS 번들이 곧 우리가 작성하는 React 코드의 빌드 결과물이다. 다만 정적 파일 서버는 로직이 없어 프로그래밍 대상이 아니라 배포 대상이며(Vercel/Netlify 또는 NestJS의 정적 서빙 겸용), 화면 렌더링은 서버가 아닌 브라우저 안의 React가 수행한다. 최초 로드 이후에는 페이지 재요청 없이 JS가 API 서버와 JSON만 주고받는다.
- **프레젠테이션**: React SPA (반응형, 태블릿 1순위). 오디오 녹음은 브라우저 MediaRecorder API (iPad Safari는 audio/mp4 포맷 대응 필요)
- **애플리케이션**: NestJS 단일 API 서버. 핵심 도메인 모듈: children, stories, sessions(대화 상태 머신 — 응답 모드 NORMAL/GUIDED/CLOSING 판정·요소 누적·장면 전환·미션 노출 판단), speech(STT/TTS 프록시), analysis(발화 분석 LLM 호출)
- **대화 엔진 구현 경계 3분리** (대화작동규칙 수정안 기준): ① **분석 LLM** — 최신 아이 발화 1건의 의도·핵심 뜻·사고 요소·유효성만 구조화(누적 요소·턴 수는 입력하지 않음) ② **서버 규칙** — 요소 누적 갱신, 모드·종료 판정, soft-cue 여부 확정 ③ **캐릭터 LLM** — 주어진 모드·반응 원칙(reactionKey)에 따라 대사만 생성. 장면 종료 시에는 생성 없이 고정 마지막 대사 조회·재생
- **데이터**: Supabase PostgreSQL. 인증은 Supabase Auth(`parents.id` = `auth.users.id`). 오디오 원문은 저장하지 않고 STT 텍스트만 저장 (팀 DB안으로 확정)
- **외부 연계**: OpenAI API (STT/GPT/TTS)
- 상세 다이어그램: `02-system-diagram.md`

## 5. 소프트웨어 구성 파악

| 계층 | 소프트웨어 | 비고 |

## 7. 네트워크 구성 파악

- 사용자 단말 → (인터넷/HTTPS) → 웹 호스팅(FE 정적 배포) + API 서버 → OpenAI API / OAuth / DB
- **HTTPS 필수**: 브라우저 마이크 권한(getUserMedia)은 secure context(HTTPS 또는 localhost)에서만 동작 — 배포 시 반드시 TLS 적용 (위험 R-02)
- 배포안: FE는 Vercel/Netlify 정적 배포, BE는 Render/Fly.io/Railway 등 PaaS 1개 — CORS 설정 필요. 단일 서버에 FE 빌드 포함 서빙도 가능(CORS 불필요, 구성 단순)
- 시연장 네트워크는 통제 불가 요소 — 모바일 핫스팟 백업 준비 (위험 R-05)
